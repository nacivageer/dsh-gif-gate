# dsh-gif-gate 决策记录

## 做什么

DSH 的 Host-only 插件：本会话第一次读 `.gif` / `.webp` 时拦下，把策略文档摆到模型眼前；
模型用 `read` 读过该文档后放行。最多拦两次，文档不存在时放行并 warning。

## 为什么这么设计

- 2026-11-08 20:42，`gif-reading` 技能（`c1b8e2d`）和 Daily Chat 的 `AGENTS.md` 规则同时落地。
- 同一晚出现两种结果：Daily Chat 20:50 的 GIF 任务，模型按规则 `read` 了策略、没调 skill；
  framedelta 21:03 catalog 已刷新出该技能，21:04 的 GIF 仍直接 `read_animation`、没读策略。
- 扫 170 会话 / 1401 轮：`skill` 共 121 次调用，`gif-reading` 0 次。
- 结论：技能作为触发换工作区就失效；工作区规则有效但只管一个工作区。约束挂到工具入口。

## 怎么跑

```sh
node --test test/gate.test.js
```

安装：`dsh plugin --profile <profile> add link:<本目录>`，或 Plugin Manager 的 `install_bundle`。

## 怎么查

- 拦截是否生效：看读 `.gif` 时返回的 `Error: [gif-gate] …`；本会话读过后再读应直接成功。
- 策略路径：环境变量 `DSH_GIF_STRATEGY` → patch `strategyPath` → 包内 `strategy-template.md`。
- 启动日志出现 `[gif-gate] strategy document not found` = 路径配错，闸门当前不生效。

## 发布决定（2026-11-11）

- 公开仓库 `nacivageer/dsh-gif-gate`，MIT，作者 72NG，版本从 `0.1.0-alpha.1` 起。
- 只公开**机制 + 一页通用模板**；个人策略文档与识图库不进仓库。
- 默认策略路径改为包内模板，删除个人绝对路径；配错时保留 fail-open 但打 warning。
- 已知边界写进 README：只管按路径读，聊天框贴图走 `dsh-read-animation` 拦不到；
  截至发布前无真实拦截记录，只有 2026-11-08 22:30 的探针。

## 不做

- 不校验模型读完策略后是否照做（只拦入口，不管执行）。
- 不覆盖贴图/附件链路（那属于 `dsh-read-animation` 的传输层）。
- 不内置任何判读规则内容——模板只是示例，策略由使用者提供。
