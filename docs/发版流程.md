# 发版流程

一句话：**版本号一个，可写的地方四处**——`package.json`、git tag、Release 资产文件名、市场 yml 的 `tarball` URL。四处一致，才算"同步"完。

## 什么时候发

**不主动发。** 2026-11-13 定：纯文档改动不占版本号，攒到下一次**行为**改动一起发。理由：版本号是分发单位，不是存档单位；市场 tarball 钉死了版本，为几行文档发一版，只是让所有人重下一次 7KB。

触发条件（有一个就发）：

- 有人反馈（例如嫌「短文档明明已经把全文摆进拒绝理由，还要再 `read` 一遍」很憨）
- 要修下面这两条已知缺陷

两条待办，都动 `index.js`、都改变行为：

1. **短文档的憨回路**。`SKELETON_LINES = 30`，策略文档 ≤30 行时拒绝理由已含全文，却仍要求 `read` 才放行。
   改法：拦一次，但那次就把状态置成"已送达"（`state.read = true`），理由末尾改成「上面就是策略全文；直接重调原来的工具，不必再 read」。
   ⚠️ **不能改成"直接放行"**——预览只存在于拒绝理由里，不拦就一次都没送达。
2. **「读过」判得太松**。`read` 带 `offset` / `limit`、或读失败，现在都算读过。
   改法：在 `tools/pre-execute` 里拒绝带 `offset` / `limit` 的 read，理由写"整份读"，并加两条测试。

## 一、插件仓（`nacivageer/dsh-gif-gate`）

本机前置：`gh` 已登录 `nacivageer`；分支是 `master`（不是 main）。

**1. 改版本号** — `package.json` 的 `version`，例如 `0.1.0-alpha.3`。
`-alpha` 后缀不许为了"两处对齐"删掉：它是成熟度声明，删掉等于对外宣布测试做完了。

**2. 跑测试**

```powershell
node --test test/gate.test.js
```

**3. 打包**（落到工作树外面：`.gitignore` 没排除 `*.tgz`）

```powershell
npm pack --pack-destination "$env:TEMP\gif-gate-pack"
tar -tzf "$env:TEMP\gif-gate-pack\dsh-gif-gate-0.1.0-alpha.3.tgz"
```

第二条看包内文件是否符合 `files` 白名单：`index.js`、`cordis.patch.yml`、`locale/*.json`、`icon.svg`、`strategy-template.md`、`README.md`。

**4. 提交并推**（路径逐个列，不用 `-A`）

```powershell
git add package.json index.js test/gate.test.js README.md docs/决策记录.md
git commit -m "release: 0.1.0-alpha.3 — <一句话>" -- package.json index.js test/gate.test.js README.md docs/决策记录.md
git push origin master
```

**5. 打 tag 并推**

```powershell
git tag -a v0.1.0-alpha.3 -m "0.1.0-alpha.3"
git push origin v0.1.0-alpha.3
```

**6. 建 Release**（带 tgz，勾 prerelease）

```powershell
gh release create v0.1.0-alpha.3 "$env:TEMP\gif-gate-pack\dsh-gif-gate-0.1.0-alpha.3.tgz" --prerelease --title "0.1.0-alpha.3" --notes "<改了什么的几句话>"
```

**7. 验下载**（302 → 200，`content-length` 与 tgz 字节数一致）

```powershell
curl.exe -sI -L "https://github.com/nacivageer/dsh-gif-gate/releases/download/v0.1.0-alpha.3/dsh-gif-gate-0.1.0-alpha.3.tgz" | Select-String '^HTTP/|^content-length'
```

## 二、市场仓（`awesome-dsh-plugin/awesome-dsh-plugin`）

**8. 改自己那条 yml** — `data/plugins/nacivageer__dsh-gif-gate.yml` 的 `tarball:` 一行。
版本号在里面出现两处：tag（`download/v0.1.0-alpha.3/`）和资产名（`dsh-gif-gate-0.1.0-alpha.3.tgz`）。

**9. 描述同步** — 如果这次改动了插件的边界表述（例如"只覆盖按文件路径读"），同一个 PR 里改 `description.en` / `description.zh`。
描述会被维护者**拿代码核对**，写不实是唯一会让好插件被打回的原因；描述里出现的数字、命令、API 名都要真的存在。

**10. 开 PR，等 CI 四项全绿**：条目数 ≤3、`dsh.bundle`、仓龄 ≥1 天、`awesome-lint` + 站点构建。全绿是**前提**，不是结论——之后维护者还会读代码。
上一次（#14708）从开到合 **4 小时 42 分**，0 条 review 评论、0 条行内评论。

**11. 合并后自动完成**：main 上重新生成两个 README、站点重建。这之后市场才装得到新版。

## 三个坑

- **`latest/download/` 不吃 prerelease。** GitHub 的 `latest` 指最新**正式版**；现在所有 release 都是 `-alpha.x`，`latest` 是空的，换那个写法会当场 404。等发了 `0.1.0` 正式版，才有资格改成"资产名固定、URL 免维护"。
- **资产名带版本 → 每版都要改 yml。** 就是第 8 步那个 PR，逃不掉，除非上面那条成立。
- **市场的"版本"不是一个字段**，就是 `tarball` 那个 URL。GitHub 上的任何 push 都不会通知市场，中间只靠那次 PR 缝合。

## 怎么查 / 怎么回滚

- 市场指向对不对：`curl.exe -sI -L <yml 里的 tarball>`，200 且字节数吻合。
- 市场 README 有没有列：在 awesome-dsh-plugin 的 `README.md` 里搜 `nacivageer/dsh-gif-gate`（文件约 3.9MB，直连下载会被重置，走代理）。
- 回滚：**tag 是锚点，旧资产永远还在**。把 yml 的 `tarball` 改回旧 URL 再开一个 PR 即可，插件仓不用动。
